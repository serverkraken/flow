01 — GESCHICHTE DES DESIGNS

Vom Dashboard zum Karteikasten

Verworfen

Topbar, Sidebar, Kachelraster

Der erste Entwurf war eine übliche Web-App: Kopfleiste mit Suche und Avatar, links Icons, in der Mitte ein Raster aus Karten mit Schatten. Es sah wie ein Dashboard aus — man überwacht damit etwas. flow wird aber gelesen und geschrieben. Der Inhalt lag in Kacheln eingesperrt, jede Karte trug einen Rahmen um zwei Zeilen Text.

Die Wende

Der Karteikasten als Bild

Ein Karteikasten hat keine Kopfleiste. Er hat Register, Karten und eine Fläche, auf der man die herausgezogene Karte liest. Daraus wurden drei Spalten: Schiene (wo bin ich), Kasten (was liegt hier), Lesesaal (was steht drin). Alles, was sonst in einer Topbar sitzt — Suche, Timer, Konto — wanderte in die Schiene.

Konsequenz

Papier statt Chrome

Wenn die Metapher Papier ist, sind Schatten, Verläufe und Glas Fremdkörper. Geblieben sind: zwei Papierflächen, Haarlinien als Struktur, Farbe ausschließlich als Herkunftsnachweis. Der Lesesaal ist die hellste Fläche im Bild — dorthin geht der Blick zuerst, und das ist Absicht.

Die sechs Regeln, aus denen alles Weitere folgt

R1

Zwei Flächen, nie mehr

Kasten auf #F1EDE2, Lesesaal auf #F8F6F0. Eine dritte Hintergrundfarbe pro Screen ist ein Fehler.

R2

Farbe erklärt Herkunft

Jede Farbe steht für eine Ebene, einen Bereich oder einen Kartentyp. Es gibt keine Farbe, die nur schön ist.

R3

Ein Zeilenmuster für alle Listen

Karten, Notizen, Buchungen, Artefakte, Treffer: dieselbe Zeile, dieselben Polster, dieselbe 3px-Schiene links.

R4

Zahlen sind Mono

Uhrzeiten, Zähler, Pfade, Tastenkürzel in JetBrains Mono mit tabellarischen Ziffern — Spalten stehen still.

R5

Alles eckig

Kein Radius — nicht an Flächen, Knöpfen, Feldern, Dialogen. Rund ist nur der Live-Punkt; gerundet nur das Gerät im Mobil-Mockup.

R6

Lesbarkeit gewinnt

Lesetext 16,5–18px auf 660–720px Satzbreite, Zeilenabstand 1,82. Kein Element darf die Spalte verbreitern.

02 B — NAVIGATIONSBAUM

Jeder Weg von der Schiene aus — und wo er endet

Der Baum listet alle Wege, die die Oberfläche anbietet: jede Zeile der Schiene, jeden Tab, jede Handlung, die eine neue Ansicht öffnet. Rechts steht, ob dafür ein Mockup existiert (Screen NN), ob ein vorhandenes Muster genügt (Muster) oder ob die Ansicht noch fehlt. Alle 41 Mockups sind im Baum erreichbar, keiner ist verwaist. Nachgewachsene Wege tragen einen Buchstaben an der Nummer — 13 A, 13 B, 15 A — damit die Reihenfolge dem Arbeitstag treu bleibt und nicht der Entstehung.

Die Einrückung folgt der Hierarchie des Kastens: Engagement → Vorhaben → Projekt → Karte. Ein Vorhaben mit Projekten trägt einen Pfeil und klappt sie auf; ein Vorhaben ohne Projekte trägt keinen und führt direkt in seine Karten. Der Pfeil ist damit kein Zierrat, sondern die Antwort auf die Frage, ob unter diesem Vorhaben noch eine Ebene liegt.

3.6 — Regeln der Anwendung

So
  • Neue Liste? Bestehendes Zeilenmuster übernehmen, nur den Typ-Ton tauschen.
  • Neue Ansicht? Farbstreifen nach Ebene oder Bereich setzen, Brotkrume anschließen.
  • Alles Zählbare in Mono, mit tabellarischen Ziffern und Einheit in Meta-Tinte.
  • Aktiver Zustand = Gewicht 700 plus 3px-Schiene, nie eine Füllfarbe.
  • Leerzustände als gestrichelter Rahmen mit einer einzigen Handlung.
  • Bewegung aus zwei Tempi (120 / 220 ms) und einer Kurve — Inhalt von unten, Seiten von rechts.
Nicht
  • Keine dritte Hintergrundfläche, keine Verläufe außer der Auswahl-Wash.
  • Keine Kartenrahmen um Lesetext — der Lesesaal ist offen.
  • Keine Ikonen-Navigation, keine Emoji, keine Piktogramme für Handlungen.
  • Keine Farbe ohne Bedeutung; Rot bleibt Fehlern und „nie“ vorbehalten, Grün dem Laufenden.
  • Keine Schatten außer Rahmen und Dialog; kein Radius — eckig ist die Regel, nicht die Ausnahme.
  • Kein Federn, kein Skalieren, keine Bewegung an Uhr, Live-Punkt oder Spaltenkanten.

3.7 — Bewegung

Papier gleitet, es federt nicht. Zwei Tempi, eine Kurve, Bewegung nur in Leserichtung — und Stille dort, wo Ruhe die Aussage ist. Die Kacheln unten laufen in Schleife, damit man das Timing sehen kann; im Produkt läuft jede Bewegung genau einmal, ausgelöst durch eine Handlung.

3.8 — Leer, lädt, kaputt

Jede Liste im Kasten hat drei Zustände neben dem vollen. Alle drei behalten das Zeilenmuster und die Spaltenbreiten — es springt nichts, wenn Inhalt nachkommt. Leer sagt, was zu tun ist. Laden zeigt Balken, keinen Kreisel. Kaputt nennt den Grund und die Wiederholung.

Der Rahmen bleibt stehen

Kopfzeile, Spaltenüberschriften und Filter gehören zum Gerüst, nicht zum Inhalt. Sie sind in allen vier Zuständen da — sonst springt der Screen beim Nachladen.

Leer ist nicht gleich leer

Teilweise kaputt bleibt sichtbar

Fällt nur das Repo aus, bleibt die Kartenliste stehen und trägt oben einen schmalen Streifen in Rot. Nie ein ganzer Screen für einen Teilfehler.

3.9 — Eingeben und Bedienen ohne Maus

Felder sind Linien, keine Kästen — geschrieben wird auf Papier, nicht in Formulare. Nur das Feld, in dem gerade steht, was zählt, bekommt eine volle Linie. Der Fokusring ist überall derselbe: 2 px Ocker, 2 px Abstand, eckig.

Worktime-Kalender v2 — Monatsansicht, Bulk-Zuweisung und die neue Skala

            
msoent · vor 3 Stunden · 14 min Lesezeit · validiert · im Agenten-Kontext, Rang 4

            

              
Der Kalender ist die Fläche, auf der Zeit sichtbar wird. v2 bringt drei Dinge: eine Monatsansicht, Bulk-Zuweisung für importierte Blöcke und eine konfigurierbare Tagesskala.

              
1 · Warum die feste Skala fällt

              
Die Wochenansicht zeichnet heute stur 06:00–20:00. Wer nachts arbeitet, sieht seine Blöcke abgeschnitten; wer nur vormittags bucht, verschenkt die halbe Fläche. Die Skala wird deshalb zum konfigurierbaren Tagesausschnitt: Start und Ende kommen aus den Einstellungen, eine Stunde bleibt bei 48px.

              
Der Import aus der alten Single-Binary-App bleibt unangetastet — die Entscheidung steht in Release-Checkliste v1.5, die Fallstricke in der Erinnerung Kalender-Scroll auf 375px.

              
              
2 · Bulk-Zuweisung importierter Blöcke

              
Importierte Sessions landen als unassigned — sichtbar, aber keinem Projekt zugeordnet. Statt jeden Block einzeln zu öffnen, wählt man künftig mehrere aus und weist sie in einem Schritt zu. Die Auswahl folgt dem Muster der Bibliothek: anhaken, Aktionsleiste unten.

              

                Hinweis
                Bulk-Zuweisung schreibt über die normale Korrektur-API — jede Änderung propagiert per SSE live in alle offenen Ansichten, auch in die TUI.
              

              
3 · Die Monatsansicht

              
Der Monat ist keine dritte Kalender-Engine, sondern eine Verdichtung: pro Tag ein Balken nach Registerfarbe, Soll-Erreichung als Füllstand, Frei-Tage als ruhige Fläche. Klick auf einen Tag öffnet die Tagesansicht.

3.2 Berechnung des Füllstands

              

                

                  go · monatsfill.go
                  
                  Kopieren
                

                
// Füllstand eines Tages, gekappt auf 1.0 —
// die laufende Session zählt anteilig mit.
func dayFill(booked, target time.Duration) float64 {
	if target == 0 {
		return 0 // freie Tage: Soll 0, Fläche bleibt ruhig
	}
	f := booked.Seconds() / target.Seconds()
	return math.Min(f, 1.0)
}

              

              
Das Tagesziel kommt aus den Einstellungen; freie Tage zählen mit Soll 0. Wie sich das mit dem Wochen-Saldo verträgt, beschreibt Worktime-Export als Usecase.
